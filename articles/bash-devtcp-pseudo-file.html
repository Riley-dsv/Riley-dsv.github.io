Bash /dev/tcp pseudo-file

Explore Bash TCP builtin pseudo-file for network communication and api debugging without external tools such as Curl, wget, bruno or postman.

What is it purpose ?

Bash TCP is supposed to open a TCP Socket on the machine and allow communication between the Client ( The Computer ) and the Distant Server. This TCP connection does not require any external program such as curl or wget. It can be extremely useful on limited environment, or to test communication between machine on the same network, on different network or even to test internet connectivity / DNS resolution. This is also possible to download web page, resources or test different APIs.

How to obtain it ?

In most cases if you obtained bash during installation or got it from official binary repo and are running bash there is nothing todo. You can verify using : 


cat < /dev/tcp/time.nist.gov/13 2> /dev/null || echo "Not available :("

What this command does is quite simple. It try to display on the terminal the content of time.nist.gov on port 13. If it fails, every error are redirected in /dev/null and won't be visible, then if it has failed, the message “Not available :(" Will appear. If it succeed it will return your local time, for me the output was :


61108 26-03-09 19:37:20 50 0 0 937.0 UTC(NIST) *

Now I hear you, you are wondering what is in the above example this weird port 13, I can't suggest you enough to read about the RFC867 (opens in a new tab)

In case the failure message shows up, you have to manually compile bash with a specific compile flags.


wget https://ftp.gnu.org/gnu/bash/bash-5.3.tar.gz
tar xvf bash-5.3.tar.gz
cd bash-5.3
./configure --enable-net-redirections
sudo make clean install

Of course, you change 5.3 with the latest bash version, you can find it by looking at the official GNU mirror (opens in a new tab)

How to interact with it ?

Interaction is simple. The pseudo-file is used with the form /dev/tcp/host/port where host is a valid hostname or IP adresse and port is an integer or service name. For example, both of those two scripts works the same : 


exec 3></dev/tcp/www.net.cn/80 && echo -e "GET / HTTP/1.0\n" >&3 && cat <&3 && exec 3>&-
# Note that port 80 become http
exec 3<>/dev/tcp/www.net.cn/http && echo -e "GET / HTTP/1.0\n" >&3 && cat <&3 && exec 3>&-

Note how the port 80 typically attached to http protocol can be swapped by the service name http. By looking at those scripts, you can see the common way to interact with /dev/tcp. First you open a File Descriptor with Read/Write permission using output redirection ( 3<>/dev/tcp/www.net.cn/80 ), then you write in this file the HTTP Request using printf or echo ( echo -e "GET / HTTP/1.0\n" >&3 )

Be aware, if you are using echo, there is a one extra newline added automatically, so you must omit one in the HEADER. In this example I am using the GET verb but you can change this for whatever fit your need such as POST, PUT, PATCH, DELETE, etc… finally you read the result and close the File Descriptor ( cat <&3 && exec 3>&- ) to avoid memory Leaks. Yes, memory leaks, I bet it's the first time you hear about memory leaks in Bash.
