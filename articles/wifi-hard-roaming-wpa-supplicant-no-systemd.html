Wifi hard roaming with wpa_supplicant without systemd

Diagnosing unstable roaming behavior between dual-band access points in my own linux environment, causing connectivity issues.

Context

I was working on my computer, when the wireless connection dropped. This was a bit annoying, because I need internet connectivity for a lot of things, but that issue was expected. since I did switched from wired to wireless connectivity the previous week.

Note that this setup does not rely on systemd nor NetworkManager. Networking is handled manually through wpa_supplicant and dhcpcd

Initial symptoms

The observed behavior was the following:

  • Lost network connectivity
  • dhcpcd unable to renew the DHCP lease
  • Reinvoking dhcpcd had no effect

Initial hypothesis

Since the issue initially appeared to involve DHCP lease renewal, the first assumption was stale state or corruption inside dhcpcd.

I manually killed every running dhcpcd process, removed remaining PID and lock files inside /run/dhcpcd, and restarted the daemon.

Connectivity temporarily came back, which initially reinforced the hypothesis. However, the issue returned shortly afterward, proving that this was not the actual root cause.

Investigation

Since the setup was intentionally minimal and did not rely on systemd tooling nor NetworkManager, I inspected dmesg directly.

The logs suggested that the issue was not DHCP-related. Instead, the wireless interface repeatedly disconnected and reassociated with different access points sharing the same SSID.

The BSSIDs were obfuscated in this article, but the logs clearly showed cyclic roaming behavior between two different access points.

After inspecting the router configuration, I discovered that the network exposed both a 2.4GHz and a 5GHz access point using the same SSID.

To confirm the hypothesis, I used: 


sudo wpa_cli -i wlp3s0 -p /run/wpa_supplicant scan_results

Which returned: 


xx:xx:xx:xx:xx:xx 5320 -57 [WPA2-PSK-CCMP][WPS][ESS] router-name
yy:yy:yy:yy:yy:yy 2412 -50 [WPA2-PSK-CCMP][WPS][ESS] router-name

Comparing the BSSIDs against the kernel logs confirmed that wpa_supplicant continuously switched between both access points.

Root cause

The issue was caused by aggressive roaming between two access points sharing the same SSID but operating on different frequency bands.

Because the setup relied directly on wpa_supplicant without higher-level network management tools, roaming decisions repeatedly oscillated between both BSSIDs.

Resolution

The permanent fix was to pin the connection to a specific BSSID inside the wpa_supplicant.conf configuration file. 


network={
  ssid="router-name"
  bssid=xx:xx:xx:xx:xx:xx
  #psk="*******************"
  psk=********************************************
}

Then every networking component was restarted: 


sudo pkill wpa_supplicant
sudo pkill dhcpcd
sudo wpa_supplicant -i wlp3s0 -B -c /etc/wpa_supplicant/wpa_supplicant.conf
sudo dhcpcd -b wlp3s0

Validation

Initial verification was performed using both raw IP connectivity and DNS resolution tests. 


ping -c 3 1.1.1.1
ping -c 3 archlinux.org

Both commands returned: 


3 packets transmitted, 3 received, 0% packet loss

After additional uptime and monitoring, the kernel logs no longer showed cyclic roaming behavior. 


[ 9926.073100] wlp3s0: authenticate with xx:xx:xx:xx:xx:xx
[ 9926.074147] wlp3s0: send auth to xx:xx:xx:xx:xx:xx (try 1/3)
[ 9926.104522] wlp3s0: authenticated
[ 9926.105456] wlp3s0: associate with xx:xx:xx:xx:xx:xx (try 1/3)
[ 9926.121590] wlp3s0: associated

Conclusion

The issue was ultimately unrelated to DHCP lease renewal and was instead caused by unstable roaming behavior between multiple access points sharing the same SSID.

Pinning the wireless configuration to a specific BSSID solved the problem permanently.
